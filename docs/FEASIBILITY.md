# 落地可行性与边界

## 已验证可行

1. 本地会话事件同时存在 `token_count`、`turn_context.model` 和 `turn_context.effort`，可以按对话阶段归因到“模型 × 思考档位”。
2. 对话 ID、标题索引、时间、工具调用、父子任务关系均有本地来源，可以生成对话排行和下钻明细。
3. Codex 插件可通过本地 MCP Server 返回交互式 UI Resource，因此看板可以在 Codex 中打开，并支持组件内刷新与周期切换。
4. 每天 23:59 可由本机 `launchd` 调用同一只读采集器生成日快照；界面内同时支持手动刷新。

## 不能承诺

1. 第三方插件不能注入或替换 Codex 原生个人信息页面；可实现的是独立插件看板或全屏组件。
2. 本地归因不是官方账单口径。云端后台处理、日志留存和日桶边界都可能造成差异。
3. 插件不展示美元费用，也不把 ChatGPT 订阅消耗套用 API 单价。
4. Codex 本地事件字段并非公开稳定数据 API；采集器必须做版本检测和降级提示。

## 刷新策略

- 默认：打开时读取最新本地快照。
- 手动：点击“立即刷新”后重新扫描增量并覆盖当日快照。
- 定时：可选安装 `launchd` 日任务，每天 23:59 执行一次。
- 不做持续轮询，避免无意义的文件扫描和界面资源占用。

定时任务的安装与卸载脚本已包含在插件包中，但不会在开发或安装阶段擅自启用；只有显式执行 `npm run scheduler:install` 才会修改本机 `LaunchAgents`。
